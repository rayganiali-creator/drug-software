# 01 — Product Requirements Document (PRD)

## 1. Product Vision
AI MedSmarter یک پلتفرم دارویی/سلامت است که بیمار، پزشک، داروساز، داروخانه و صنعت دارو را حول یک
«حقیقت واحد و قابل‌ممیزی» از نسخه، برنامهٔ مصرف، پایبندی و عوارض جانبی به هم وصل می‌کند و یک دستیار هوشمند
**اطلاعات‌محور و ایمنی‌محور** ارائه می‌دهد.

اصول محصول:
1. **ایمنی بالاتر از هوشمندی**: تصمیم‌های بالینی قطعی (تداخل، منع مصرف، دوز) را موتور قواعد قطعی و انسان می‌گیرد، نه LLM.
2. **بیمار مالک داده است**: هر دسترسی با Consent و Audit.
3. **همه‌چیز منبع‌دار**: هر پاسخ دارویی به منبع و نسخهٔ دانش ارجاع دارد.
4. **کمک به تصمیم، نه جایگزین متخصص**.

## 2. Problem Statement
> فقط مسائل زیر «فرض» هستند و باید با تحقیق کاربر تأیید شوند (**UNKNOWN**: هیچ تحقیق کاربری در دست نیست → D-02).

- بیماران برنامهٔ دارویی پیچیده را فراموش یا اشتباه مصرف می‌کنند (Non-adherence).
- اطلاعات دارو پراکنده و گاه نامعتبر است؛ بیمار از چت‌بات‌های عمومی پاسخ ناایمن می‌گیرد.
- پزشک/داروساز دید کمی از پایبندی و عوارض واقعی بیمار بین دو ویزیت دارند.
- گزارش عوارض جانبی (ADR) کم‌گزارش و ساخت‌نیافته است.
- صنعت دارو داده واقعی و de-identified کم دارد (و باید فقط با رضایت و تجمیع).

| Pharma Industry User | تحلیل تجمیعی، گزارش ADR پس از بازار | **فقط** داده تجمیعی/de-identified؛ هرگز دادهٔ فردی |

## 4. User Journeys (خلاصه)
**J1 بیمار — از نسخه تا مصرف:** ثبت‌نام + MFA → پیوند به پزشک/دریافت نسخه (دستی/اسکن/Provider) → تأیید آیتم‌ها →
تولید MedicationSchedule → یادآوری → ثبت مصرف (Taken/Skipped/Late) → پایبندی → هشدار در صورت افت.

**J2 بیمار — پرسش از دستیار:** سؤال دربارهٔ دارو → Safety pre-check → RAG از KnowledgeBase → پاسخ با ارجاع +
Disclaimer → در صورت علامت خطر (Red-flag) ارجاع اورژانسی، بدون تحلیل LLM.

**J3 بیمار — گزارش عارضه:** ثبت علامت → پیشنهاد ارتباط با دارو (کمک‌کننده، نه تشخیص) → ارجاع به داروساز/پزشک →
ثبت AdverseEvent با Consent برای اشتراک.

**J4 پزشک:** ورود (MFA) → درخواست دسترسی به بیمار (AccessGrant/Consent) → ایجاد نسخه → اجرای Clinical Safety
Check (تداخل/آلرژی/بارداری…) → پذیرش/رد هشدار با ثبت دلیل → امضا/ارسال.

**J5 داروساز:** دریافت نسخه → بازبینی + هشدار ایمنی → مداخلهٔ دارویی (Intervention) → تحویل → ثبت مشاوره/ADR.

**J6 صنعت دارو:** داشبورد تجمیعی (حداقل اندازهٔ گروه k) → سیگنال ADR تجمیعی → درخواست پژوهش با Consent صریح.

**J7 Admin/Editor محتوا:** بارگذاری منبع دانش → پردازش → پیش‌نمایش → تأیید دو نفره → انتشار نسخهٔ جدید KnowledgeVersion.

## 5. Functional Requirements
شناسه‌ها `FR-<حوزه>-nn`؛ اولویت: **M**=MVP، **S**=Should (پس از MVP)، **F**=Future.

### Identity & Access
- FR-ID-01 (M) ثبت‌نام/ورود با ایمیل یا موبایل؛ شیوهٔ تأیید هویت **UNKNOWN** (D-05).
- FR-ID-02 (M) MFA اجباری برای Physician/Pharmacist/Admin؛ اختیاری‌ـتشویقی برای Patient.
- FR-ID-03 (M) RBAC + ABAC (رابطهٔ درمانی، Consent، داروخانهٔ عضو).
- FR-ID-04 (S) مدیریت دستگاه‌ها و ابطال نشست.

### Patient / Physician / Pharmacist / Pharmacy
- FR-PA-01 (M) پروفایل بیمار (سن/جنس، آلرژی، شرایط، بارداری/شیردهی – فیلدها با تأیید بالینی، D-06).
- FR-PH-01 (M) پروفایل پزشک/داروساز با وضعیت تأیید مجوز (فرایند **UNKNOWN**).
- FR-PY-01 (M) داروخانه و عضویت داروسازان.
- FR-PA-02 (S) Caregiver/نمایندهٔ بیمار (D-03).

### Medication Knowledge
- FR-MD-01 (M) کاتالوگ دارو، ماده مؤثره، سازنده؛ جستجوی فازی (فارسی/انگلیسی).
- FR-MD-02 (M) نمایش برگه اطلاعات دارو از KnowledgeBase با منبع و نسخه.
- FR-MD-03 (S) بارکد/تصویر بستهٔ دارو (نیاز به منبع بارکد: **UNKNOWN**).

### Prescription & Schedule
- FR-RX-01 (M) ایجاد نسخهٔ دستی توسط پزشک؛ ثبت نسخهٔ خودگزارشی بیمار (برچسب «تأییدنشده»).
- FR-RX-02 (M) چرخهٔ عمر نسخه: Draft→Issued→(Dispensed)→Completed/Cancelled/Expired.
- FR-RX-03 (M) تولید برنامهٔ مصرف از PrescriptionItem (دوز، تناوب، مدت).
- FR-RX-04 (F) اتصال به سامانهٔ نسخهٔ الکترونیک (Provider؛ **UNKNOWN** که کدام، D-07).

### Intake & Adherence
- FR-IN-01 (M) یادآوری Push/SMS(?)؛ کانال SMS **UNKNOWN** (D-08).
- FR-IN-02 (M) ثبت مصرف و Undo.
- FR-AD-01 (M) شاخص پایبندی (تعریف دقیق فرمول: تأیید بالینی، D-09).
- FR-AD-02 (S) هشدار به پزشک/داروساز با Consent.

### Symptoms & ADR
- FR-SY-01 (M) ثبت علامت ساخت‌یافته (کدگذاری: **UNKNOWN**، D-10).
- FR-AE-01 (M) ثبت AdverseEvent و اتصال به دارو.
- FR-AE-02 (S) خروجی برای گزارش رسمی به نهاد ناظر (**UNKNOWN** نهاد/قالب، D-11).

### AI Assistant
- FR-AI-01 (M) پرسش‌وپاسخ دارویی با RAG، ارجاع اجباری، امتناع در نبود منبع.
- FR-AI-02 (M) Red-flag detection قطعی (بدون LLM).
- FR-AI-03 (M) پاسخ‌ها درباره بیمار خاص فقط با Consent و از طریق Toolهای مجاز.
- FR-AI-04 (S) خلاصه‌سازی تاریخچه برای پزشک (فقط خلاصه، با ارجاع به رکورد).
- FR-AI-05 (S) استخراج آیتم نسخه از تصویر/متن → **پیشنهاد**، همیشه با تأیید انسان.

### Clinical Safety
- FR-CS-01 (M) بررسی تداخل دارو-دارو، دارو-آلرژی، تکرار درمان (Duplicate Therapy).
- FR-CS-02 (S) دوز/سن/کلیه/کبد/بارداری (نیاز به منبع دانش مجاز، **UNKNOWN**).
- FR-CS-03 (M) هر هشدار: شدت، دلیل، منبع، اقدام پیشنهادی، ثبت override.

### Consent / Audit / Notifications / Analytics / Integrations
- FR-CO-01 (M) Consent ریزدانه، قابل‌ابطال، نسخه‌دار.
- FR-AU-01 (M) Audit تغییرناپذیر برای همهٔ دسترسی/تغییر PHI.
- FR-NO-01 (M) اعلان Push/Email؛ ترجیحات کاربر؛ Quiet hours.
- FR-AN-01 (S) داشبورد تجمیعی با k-anonymity.
- FR-IG-01 (S) چارچوب Provider/Adapter، Retry، DLQ.

### Clients
- FR-CL-01 (M) Web Dashboard (React) برای پزشک/داروساز/ادمین.
- FR-CL-02 (M) Mobile (Flutter) برای بیمار (پزشک/داروساز: **UNKNOWN**، D-12).
- FR-CL-03 (F) Browser/Share Extension: اشتراک متن/تصویر/لینک دارو به اپ؛ **بدون** خواندن صفحات دیگر. (D-13)

## 6. Non-Functional Requirements
اعداد زیر **پیشنهادی**اند و باید تأیید شوند (D-14).
| حوزه | هدف |
|---|---|
| Availability | 99.5% MVP، 99.9% پس از Pilot |
| Latency | API غیر AI p95 < 300ms؛ AI (RAG) p95 < 8s (streaming) |
| Safety | ۱۰۰٪ هشدارهای تداخل از موتور قطعی، نه LLM |
| Auditability | ۱۰۰٪ دسترسی PHI ثبت؛ Log غیرقابل‌ویرایش (hash-chain) |
| Security | MFA حرفه‌ای‌ها، رمزنگاری در حمل و ذخیره، تست نفوذ قبل از Pilot |
| Privacy | Data minimization، Retention اتوماتیک، حذف/خروجی داده |
| Scalability | MVP: تا ~۱۰⁴ کاربر فعال (فرض؛ UNKNOWN) |
| Observability | Trace/Log/Metric با correlation-id؛ بدون PHI در Log |
| Localization | فارسی (RTL) + انگلیسی؛ تقویم جلالی/میلادی (D-15) |
| Accessibility | WCAG 2.1 AA |
| Offline | موبایل: نمایش برنامه و ثبت مصرف آفلاین با همگام‌سازی |
| Backup/DR | RPO ≤ 15min، RTO ≤ 4h (پیشنهاد) |
| Compliance | **UNKNOWN** تا حوزهٔ قضایی مشخص شود (D-01) |
| AI Quality | Groundedness/Refusal/Red-flag recall با Eval Suite دروازهٔ Release |

## 7. MVP Scope
**داخل MVP (پیشنهاد):** Identity+MFA، پروفایل‌ها، Consent، Audit، کاتالوگ دارو + KB محدود، نسخه دستی،
برنامه و مصرف، پایبندی پایه، علائم/ADR پایه، موتور تداخل پایه، دستیار RAG **فقط-اطلاعاتی**، Web (پزشک/داروساز)،
Mobile (بیمار)، اعلان.

**خارج از MVP:** Integration واقعی، Analytics صنعت، Extension، OCR نسخه، دوزینگ بالینی، Caregiver، پرداخت/بیمه.

MVP قابل‌ارائه فقط پس از تصمیم‌های D-01, D-16 (منبع دانش)، D-17 (LLM Provider).

## 8. Future Features
اتصال Provider نسخه/داروخانه/بیمه، OCR نسخه، Extension، تحلیل صنعت، Caregiver، تلمدیسین، سیگنال‌یابی ADR،
شخصی‌سازی یادآوری، پشتیبانی چندزبانه، اتصال دستگاه پوشیدنی (**UNKNOWN**).

## 9. Out of Scope (صریح)
تشخیص بیماری، تجویز خودکار، تعیین یا تغییر دوز توسط AI، جایگزینی داروساز/پزشک، فروش دارو (**UNKNOWN**، D-18).
