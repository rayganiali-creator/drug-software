# 04 — Security, privacy, audit

* **Server-side only.** Every route requires the catalog permission and membership of the owning organization; the organization of an existing record comes from the record. Tests: 12 route/verb combinations return 401 without a token; the pharmacist and the pharmacy administrator of the same organization succeed; a pharmacist is refused on the other organization's route and on a record owned by it; patients, physicians, industry, researcher, system admin and an unrelated physician are refused on read, list and create; a missing record and another organization's record return the identical response.
* **No patient data in the pharmacy tables.** Events store no patient identifier. A concern linked to a ProductTrace record stores identifiers copied from it (product name, batch, expiry, manufacturer, GTIN — **not** patient data) plus the pseudonymous patient id for audit tracing; **the id is never returned** by any response (tested). The reporter's free text can contain anything typed; the UI says not to enter identifying details, and **screening would not be anonymization — none is claimed**.
* **Consent and revocation.** The ProductTrace link is made only when the caller passes that patient's own relationship and `products` consent **at link time**; a patient who has not consented can never have a record linked (tested with a patient who has no relationship). Because the snapshot holds batch identifiers only, later revocation of consent does not expose patient data through the concern; the retained snapshot is a product fact. [OPEN] whether the legal basis for retaining a snapshot after revocation needs separate review.
* **Audit** actions: `PHARMACY_SAFETY_EVENT_CREATED`, `PHARMACY_SAFETY_ENTRY_ADDED`, `PHARMACY_SAFETY_STATUS_CHANGED`, `PRODUCT_CONCERN_CREATED`, `PRODUCT_CONCERN_REPORT_PROPOSED`, `PHARMACY_SAFETY_ACCESSED` (record reads). Each line has actor, resource type/id, source, correlation id and **enum names plus the organization id only**. A test writes distinctive text into descriptions, medicine, product, batch, notes and reasons and asserts none appears anywhere in the audit log.
* **Idempotency and concurrency:** a unique `(organization, reporter, client request id)` index; stale `version` → 409.
* **No outbound path:** no HTTP client, queue, adapter or integration reference in the module; tests check the assembly references and that a manufacturer-report note leaves the existing outbox unchanged. No insurer access exists.
* **Not production-ready:** no DPIA, penetration test, retention policy or independent-reviewer rule for these records.
