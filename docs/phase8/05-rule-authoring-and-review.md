# 5. Rule authoring and independent review

Web: `/app/workspace|physician|pharmacist/rules` (list with status, activation and reasons) → rule page → editor `/rules/new`, `/rules/:id/:version/edit`.
* **Authoring** (`clinicalrules.author`): form for identity, area, severity/urgency, template, criteria parameters, population, limitations, evidence rows, test cases (JSON). Only the fixed criteria kinds can be chosen (`GET /clinical-rules/options` is derived from the validator); no code, SQL or free query. "Start from an existing version" prefills the next version. A draft is edited in place only by its author and only while Draft (`PUT`); after submission the content is frozen (a change = new version). Demonstration rules and `DEMO-` ids cannot be edited or created.
* **Provenance shown**: every source with validation status, version, publication date or "not recorded" (never invented), review status.
* **Review** (`clinicalrules.review`, a different permission from authoring): the page shows author and reviewer by name, dates, the rule's tests, the history, `approvalBlockers` for *this* viewer (including `review.separation_of_duties`), and approve/reject controls. Controls are hidden/disabled for the author as a convenience; **the server decides**: author ≠ reviewer in the service and the permission split, activation policy, evidence policy, effective date, and the rule's test cases are re-run at approval; every refusal is audited and shown in words.
* **Activation policy unchanged**: an approved flag alone does nothing. Active needs a different reviewer with a review time, a passed effective date, no retirement, ≥1 evidence and no demonstration evidence and ≥1 *validated*, ≥1 test case. Unverified / needs-validation sources can be recorded for drafting and research and **never** make a rule eligible (UI text and tests).
* Version comparison is a field-by-field table of two versions of the same rule (client side, no new endpoint).
* **State preserved:** no clinically approved rule exists. The built-in demonstration rules are drafts that can never be approved; QA/test fixtures use clearly labelled "TEST FIXTURE" evidence in throw-away databases only.
* Persian wording on these pages and in the new messages is unreviewed (banner shown in fa).
